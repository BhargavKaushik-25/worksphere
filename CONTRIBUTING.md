# Contributing to WorkSphere

Thank you for your interest in contributing to WorkSphere.

This document describes the development workflow, coding expectations, and contribution process for the project.

---

# 1. Before You Start

Before contributing, please ensure that you have:

- Read the project README.
- Reviewed the Engineering Handbook.
- Understood the project architecture.
- Read the coding principles.
- Read the Git workflow guidelines.

---

# 2. Development Workflow

The recommended workflow is:

1. Pull the latest changes from `main`.
2. Create a new feature branch.
3. Implement your changes.
4. Test your implementation.
5. Update documentation if required.
6. Commit using meaningful commit messages.
7. Push your branch.
8. Open a Pull Request.

---

# 3. Branch Naming

Use the following conventions:

| Type | Format |
|-------|---------|
| Feature | `feature/short-description` |
| Bug Fix | `bugfix/short-description` |
| Documentation | `docs/short-description` |
| Hotfix | `hotfix/short-description` |

Examples:

```
feature/task-comments
bugfix/login-validation
docs/api-guidelines
```

---

# 4. Commit Messages

Follow the Conventional Commits format.

Examples:

```
feat: implement task assignment
fix: resolve authentication issue
docs: update deployment guide
refactor: simplify notification service
test: add workspace integration tests
```

---

# 5. Coding Standards

All code should follow the standards defined in the Engineering Handbook.

Important principles include:

- Readability
- Simplicity
- Maintainability
- Proper documentation
- Appropriate testing

---

# 6. Pull Requests

Every Pull Request should include:

- Purpose of the change
- Related issue (if applicable)
- Testing performed
- Documentation updates
- Screenshots (for UI changes)

---

# 7. Code Review

All contributions are reviewed before merging.

Review focuses on:

- Correctness
- Maintainability
- Security
- Performance
- Testing
- Documentation

---

# 8. Documentation

Documentation should be updated whenever:

- New features are added.
- Existing behavior changes.
- APIs change.
- Architecture changes.
- Deployment changes.

---

# 9. Questions

If you are unsure about a design or implementation decision, discuss it before starting significant development.

---

# Thank You

Your contributions help improve WorkSphere and are greatly appreciated.
